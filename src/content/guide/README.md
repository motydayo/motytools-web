# 使い方ガイド記事の書き方（記事担当向け）

このフォルダに `.md` ファイルを1本置くと、`https://motytools.com/guide/<ファイル名>/` の記事ページになります。
一覧（`/guide/`・`/guide/app/<アプリ>/`）・サイトマップ・構造化データ・アプリ誘導ブロックは自動で付きます。
このREADMEと `_` で始まるファイルは記事として公開されません。

## 1. ファイル名（＝URL）

- 半角の英小文字・数字・ハイフンだけ。例: `instagram-recipe-hozon.md` → `/guide/instagram-recipe-hozon/`
- 日本語のファイル名は使わない。公開後に名前を変えるとURLが変わるので変えない
- `app` という名前は使えない（`/guide/app/` と重なる）

## 2. 先頭の設定（frontmatter）

```yaml
---
title: インスタのレシピを保存する方法4つ｜あとで材料名で探せる残し方
description: Instagramで見つけたレシピを保存する方法を4つ比べます。……（80〜120字）
app: recipescrap
primary: インスタ レシピ 保存
publishedAt: 2026-10-12
updatedAt: 2026-10-12
faq:
  - q: インスタで投稿を保存すると、投稿した人に知られますか？
    a: 誰が保存したかは投稿者に知らされません。……
draft: false
---
```

| 項目 | 必須 | 中身 |
|---|---|---|
| `title` | 必須 | 記事の見出し＝検索結果のタイトル。8〜60字（目安32〜40字）。検索語を前に置く |
| `description` | 必須 | 検索結果の説明文。40〜160字（目安80〜120字） |
| `app` | 必須 | どのアプリの記事か。下の「アプリslug一覧」から1つ。違う値だとビルドが止まる |
| `primary` | 必須 | 狙う主な検索語（例: `家賃管理 エクセル アプリ`）。画面には出ない。管理用 |
| `publishedAt` | 必須 | 公開日 `YYYY-MM-DD` |
| `updatedAt` | 任意 | 更新日。書き直したら必ず更新する（サイトマップと「◯月◯日更新」に出る） |
| `faq` | 任意 | よくある質問。`q` と `a` の組を3〜5個。**`a` はプレーンテキストだけ**（リンク・太字・HTMLは書かない。構造化データにそのまま入るため） |
| `draft` | 任意 | `true` にすると公開されない（一覧・サイトマップからも消える） |

## 3. 本文

普通のMarkdownで書きます。見出しの使い方だけ決まりがあります。

- **`#`（h1）は書かない**。タイトルが自動でh1になる
- 大見出しは `##`（h2）。**h2が目次になる**（2つ以上で目次が出る）
- 小見出しは `###`（h3）。h4以下は使わない
- 表・箇条書き・番号付きリスト・引用（`>`）・太字（`**`）が使える。斜体は使わない
- 画像は `public/guide/<ファイル名>/` に置き、`![説明](/guide/<ファイル名>/01.webp)` で貼る（WebPで、差し替えるときはファイル名も変える）
- 絵文字は使わない

## 4. 使える部品

### アプリ誘導ブロック（記事の途中）

本文の中に、**その1行だけの段落**として書くと、そこにアプリのアイコン・名前・一言・App Storeバッジ・紹介ページへのリンクが入ります。

```markdown
[[app]]
```

- `[[app]]` … frontmatter の `app` のアプリ
- `[[app:ooya-note]]` … 別のアプリを指定（slugは下の一覧から）
- 1本の記事に1〜2個まで。「読者がアプリを欲しくなった直後」（手作業の大変さを説明し終えたところ）に置く
- 1つも書かなかった場合、h2が3つ以上ある記事なら**真ん中のh2の直前に自動で1つ**入る

記事の最後のアプリ誘導ブロック（機能3つ・料金つき）、よくある質問、同じアプリの関連記事、ほかのアプリへの導線は、書かなくても自動で付きます。

### 補足ボックス

```html
<div class="callout">

注意したいことや、先に知っておくと良いことを書きます。中ではMarkdownも使えます。

</div>
```

（`<div>` の直後と `</div>` の直前に空行を入れる）

## 6. 書く前・出す前の確認

- アプリの機能・料金・無料の範囲は、各LPと `src/data/apps.ts` に書いてあることだけを書く。分からないことは書かない
- 他社サービス（Instagram・エクセル等）の操作手順は、変わりやすいので言い切りすぎない
- 税金・法律・医療などは一般的な事実までにして、個別の判断は専門家・公式窓口へ案内する
- 個人の氏名・メールアドレスは書かない。問い合わせは各アプリの「ご意見・要望」へ
- 標語（「◯◯を、△△する。」）で始めない。最初の段落で「この記事で何が分かるか」を書く
- `npm run build` が通ることを確認する（frontmatter の書き間違いはここで止まる）
